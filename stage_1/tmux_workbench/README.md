# 实战项目：基于 tmux 的 C++ 微服务开发与高并发压测工作台

> 本项目通过一个真实的**C++ TCP 服务端 + 并发压测客户端 + 系统资源实时监控**，带你体验后端开发工程师在日常工作中是如何利用 `tmux` 构建全流程高效开发环境的。

---

## 一、 tmux 在实际工作中的典型应用场景

在企业级后端/系统开发中，`tmux` 绝不是一个花哨的玩具，而是支撑日常工程效率的核心工具：

1. **“一屏尽收眼底”的闭环联调**：
   * **窗格 1**：跑主服务并实时打印业务日志。
   * **窗格 2**：跑压测程序或 Curl 脚本，随时注入流量。
   * **窗格 3**：跑监控脚本（监控 CPU、内存、FD 数量、TCP 连接状态）。
   * **窗格 4**：用 GDB 附加或写 Git 提交。
2. **长耗时任务守护（编译与训练）**：
   * 公司大型 C++ 项目一次全量编译可能需要 30 分钟到 1 小时，或者在服务器上训练大模型、跑几小时的压测。在 `tmux` 里运行后，你可以直接合上笔记本电脑下班；第二天到工位重新 `tmux attach`，编译和测试依然完好无损地在跑。
3. **环境一键拉起（自动化工作流）**：
   * 高级工程师会将自己常用的排错分屏布局写成 Shell 脚本（如本项目提供的 `start_workbench.sh`），输入一条命令即可瞬间在多窗格中分别启动数据库、服务、日志追踪器，无需每次手动分屏输入命令。

## 二、 实践项目结构

本项目位于目录：`projects/tmux_workbench/`

```text
projects/tmux_workbench/
├── server.cpp           # C++ TCP 回显微服务（监听 8080 端口，统计活跃连接与总请求）
├── client.cpp           # 多线程并发压测客户端（可自定义并发线程数与请求数）
├── monitor.sh           # 实时系统探针（每秒监控 server 的 PID、CPU、内存、FD 数量、TCP 状态）
├── start_workbench.sh   # 核心：利用 tmux CLI 自动化创建并分屏启动整个工作台
└── README.md            # 本项目指导说明
```

### 自动化工作台布局预览

## 三、 快速启动与实操指引

### 第一步：赋予执行权限并一键启动
在 WSL 终端中切换到项目目录：
```bash
cd /mnt/d/Project/Linux_learning/projects/tmux_workbench
chmod +x start_workbench.sh monitor.sh
./start_workbench.sh
```

**此时神奇的一幕发生了**：  
屏幕瞬间被切分为 3 个窗格：
1. **左上方**：`server` 已经编译运行，每秒打印一次全局请求统计。
2. **右侧**：`monitor.sh` 已经自动探测到 `server` 的 PID，正在实时刷新 CPU/内存、FD 计数和 TCP 端口连接。
3. **左下方**：光标停留在交互终端，等待你的指令。

---

### 第二步：实战演练与关键观察

#### 1. 发起高并发压测
在左下方（光标所在窗格）输入以下命令回车：
```bash
./client 30 200
```
（解释：启动 30 个并发连接，每个连接发送 200 次请求）

#### 2. 观察右侧监控窗格的联动
当压测开始时，立刻将视线转移到右侧仪表盘：
* **活跃连接数**：瞬间升至 30。
* **FD（文件描述符）计数**：从初始的 3~4 个，瞬间攀升到 30+（直观印证：**在 Linux 下每个 TCP 连接都对应一个 FD**）。
* **TCP 连接状态**：`ESTABLISHED` 状态的数量立刻变为 30。
* 当压测结束，客户端关闭连接，FD 和连接数瞬间回落。

---

### 第三步：在当前工作台中演练 tmux 必知必会快捷键

#### 1. 窗格之间移动光标
* 按下 `Ctrl + b`，松手，再按 `↑`（向上）：光标跳转到左上方的服务端窗格。
* 按下 `Ctrl + b`，松手，再按 `→`（向右）：光标跳转到右侧的监控窗格。
* 按下 `Ctrl + b`，松手，再按 `←`（向左）：光标跳回左侧。

#### 2. 临时全屏放大（Zoom）某个窗格
* 假设右侧监控内容太多、字体不够看：
  * 把光标移到右侧窗格，按下 `Ctrl + b`，松手，按 `z`。
  * **效果**：右侧窗格瞬间全屏铺满整个终端！
  * 仔细看清楚后，再次按下 `Ctrl + b`，松手，按 `z`，立刻恢复三屏原貌。

#### 3. 会话挂起（Detach）与重连恢复
* 按下 `Ctrl + b`，松手，按 `d`。
* **效果**：你退出了 tmux，回到了你原本的 WSL 命令行提示符。
* 验证后台任务是否存活：
  ```bash
  tmux ls
  ```
  你会看到 `backend_lab: 1 windows (created ...)` 依然在后台静默运行。
* 重新连接恢复现场：
  ```bash
  tmux attach -t backend_lab
  ```
  所有窗格、打印的数据、监控毫秒级无缝恢复！

#### 4. 彻底销毁工作台
完成演练后，退出并销毁会话：
```bash
tmux kill-session -t backend_lab
```

## 四、 进阶技巧：配置鼠标滚轮与点击（推荐）

默认情况下，tmux 窗格无法用鼠标滚轮翻看历史输出。只需创建一个配置文件即可开启现代化支持：

在 WSL 终端中执行：
```bash
cat << 'EOF' > ~/.tmux.conf
# 开启鼠标支持（支持鼠标滚轮翻页查看历史日志、鼠标点击切换窗格、鼠标拖拽调整窗格大小）
set -g mouse on

# 增加历史滚动缓冲区行数
set -g history-limit 10000

# 提升颜色支持
set -g default-terminal "screen-256color"
EOF

# 立即重新加载配置
tmux source-file ~/.tmux.conf
```
配置完成后，在任意 tmux 窗格中，你可以直接**用鼠标点击切换窗格**、**用鼠标滚轮往上滚动查看几百行前的日志**！
